## ❌ 缺点（面试官会质疑的地方）

### 1. 核心技术依赖外部 API（深度不够）

**问题**：
- 核心能力（AI 回答）完全依赖 DeepSeek API
- 你只是「调用 API + 包装一下」，没有自己的算法/模型

**面试官会问**：
> "如果 DeepSeek 不给你用，你这个项目还能跑吗？"  
> "你自己做了什么？只是调 API 吗？"

**影响**：
- 技术深度评分：5/10（中等偏下）
- 简历上写「AI 安全助手」会显得夸大

### 建议的简历描述（诚实版）

**项目名称**：Aegis-AI - 基于 RAG 的安全情报检索与代码审计系统

**项目描述**：
- 开发了一个前后端分离的安全工具，结合向量数据库（ChromaDB）和 RAG 技术，实现 CVE 漏洞快速检索
- 实现了基于 AST 的代码静态分析引擎，结合 AI 生成审计报告
- 使用 FastAPI + Angular 构建，包含错误重试、日志系统、缓存机制等工程化特性

**技术栈**：Python、FastAPI、Angular、TypeScript、ChromaDB、AST 分析、RAG

**项目亮点**：
- 实现了 RAG 检索增强生成流程（向量检索 + AI 生成）
- 设计了 AST 静态分析引擎，能检测高危函数调用
- 实现了缓存、限流、日志等生产级特性

**这样写的好处**：
- ✅ 诚实（不夸大）
- ✅ 能证明多项技能（前后端、数据库、AI、安全）
- ✅ 有技术亮点（RAG、AST）

## 💡 改进建议（让它更"简历友好"）

### 优先级 1：扩展知识库（最重要）

**问题**：只有 7 条数据，演示效果差

**改进**：
- 接入 MITRE CVE 数据库（公开数据，免费）
- 至少做到 100+ 条 CVE 数据
- 定期更新（可以写个爬虫脚本）

**简历加分**：

- "知识库包含 100+ 条 CVE 漏洞信息"

**时间投入**：1-2 天

### 优先级 2：增加技术深度（证明你不是只会调 API）

**简历加分**：
- "实现了基于 LLaMA 的本地安全问答模型"

- "开发了可扩展的 AST 规则引擎"

**时间投入**：3-5 天（选项 C 最简单，1-2 天）

---

### 优先级 3：完善项目文档（证明工程能力）

**改进**：

## 🎓 面试官会问的问题（提前准备）

### 技术问题

1. **"RAG 的原理是什么？你是怎么实现的？"**
   - 准备：向量检索 → 上下文增强 → AI 生成
   - 能说出：ChromaDB 向量化、余弦相似度、阈值判断

2. **"AST 分析是怎么做的？能检测哪些漏洞？"**
   - 准备：Python `ast` 模块、访问者模式、高危函数列表
   - 能说出：`eval`、`os.system`、`subprocess.call` 等

3. **"为什么用 ChromaDB？和传统数据库有什么区别？"**
   - 准备：向量相似度检索、语义搜索、传统数据库只能精确匹配

### 项目问题

4. **"这个项目能解决什么问题？有什么优势？"**
   - 准备：快速查 CVE、代码审计、本地部署（数据不出域）
   - 不要说："比 ChatGPT 强"（会被质疑）

5. **"知识库只有 7 条数据，怎么扩展？"**
   - 准备：MITRE CVE 爬虫、向量化流程、定期更新脚本

6. **"如果 DeepSeek API 不能用，怎么办？"**
   - 准备：可以替换为其他 API（OpenAI、Claude），或者本地模型（LLaMA）

### 工程问题

7. **"这个项目能上线吗？还需要做什么？"**
   - 准备：认证/授权、单元测试、监控告警、Docker 部署

8. **"缓存是怎么实现的？为什么用内存缓存不用 Redis？"**
   - 准备：TTL + LRU、简单场景够用、后续可以扩展 Redis
